# رقعة — Riqaa

لعبة سيطرة على الأراضي (Territory / Area Control) متعددة اللاعبين داخل **Telegram Mini App**.
اللاعب يخرج من أرضه، يرسم مسارًا، ثم يعود ليضم ما أحاط به. من يقطع مسارك يُخرجك من الجولة.

> هذه **المرحلة الأولى**: أساس قابل للعب مع بوتات، وهوية اللاعب من تيليجرام.
> لا يوجد Multiplayer حقيقي ولا اقتصاد ولا متجر — البنية مهيأة لها لاحقًا فقط.

---

## التشغيل السريع

```bash
npm install          # تثبيت كل الحزم (npm workspaces)
cp .env.example .env # اختياري — يعمل المشروع بقيم افتراضية بدونه
npm run dev          # الخادم على 3000 + واجهة التطوير على 5173
```

ثم افتح <http://localhost:5173> في المتصفح. خارج تيليجرام تدخل اللعبة بـ**وضع ضيف** (للتطوير فقط).

### تشغيل نسخة الإنتاج محليًا

```bash
npm run build   # يبني الحزم + الخادم + الواجهة
npm start       # خادم واحد على المنفذ 3000 يقدّم الـAPI والواجهة معًا
```

### أوامر أخرى

| الأمر | الغرض |
| --- | --- |
| `npm test` | اختبارات محرك اللعبة (استحواذ، قطع المسار، البوتات، محاسبة المساحة) |
| `npm run typecheck` | فحص أنواع TypeScript في كل المشروع |
| `npm run dev:server` / `npm run dev:miniapp` | تشغيل طرف واحد فقط |

## الربط بتيليجرام

1. أنشئ بوتًا من [@BotFather](https://t.me/BotFather) واحصل على التوكن.
2. ضع التوكن في `.env`:
   ```
   TELEGRAM_BOT_TOKEN=123456:AA...
   SESSION_SECRET=<نص عشوائي طويل>
   DEV_ALLOW_GUEST=false
   ```
3. انشر المشروع على عنوان **HTTPS** عام (تيليجرام لا يفتح http).
4. في BotFather: `/newapp` أو `/setmenubutton` ← ضع رابط اللعبة.
5. افتح اللعبة من داخل تيليجرام.

**التحقق من الهوية:** الواجهة ترسل `Telegram.WebApp.initData` كما هي، والخادم يتحقق منها بالطريقة الرسمية:

```
secret = HMAC_SHA256(key = "WebAppData", data = <bot token>)
hash   = HMAC_SHA256(key = secret,      data = <data_check_string>)
```

ولا تُقبل أي بيانات مستخدم قبل نجاح هذا التحقق، ولا يُقبل `initData` أقدم من `INIT_DATA_MAX_AGE`.
بعد التحقق يُصدر الخادم رمز جلسة موقَّعًا يُستخدم في بقية النداءات.

### متغيّرات البيئة

| المتغيّر | الافتراضي | الوصف |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | فارغ | بدونه يُرفض كل دخول عبر تيليجرام |
| `SESSION_SECRET` | قيمة تطوير | مفتاح توقيع رموز الجلسة — غيّره في الإنتاج |
| `DEV_ALLOW_GUEST` | `true` | يسمح بدخول ضيف خارج تيليجرام — **أوقفه في الإنتاج** |
| `MONGODB_URI` | فارغ | بدونه يعمل المشروع بتخزين مؤقت في الذاكرة |
| `MONGODB_DB` | `riqaa` | اسم قاعدة البيانات |
| `PORT` / `HOST` | `3000` / `0.0.0.0` | عنوان الخادم |
| `CORS_ORIGIN` | `*` | الأصول المسموح لها |

## النشر

المشروع يعمل على أي استضافة تدعم Node.js — خادم واحد يقدّم الـAPI وواجهة اللعبة معًا.

```bash
npm install
npm run build     # يبني الحزم + الخادم + الواجهة
npm start         # يستمع على process.env.PORT (افتراضيًا 3000) و 0.0.0.0
```

### على Render

| الحقل | القيمة |
| --- | --- |
| Environment | Node |
| Build Command | `npm install --include=dev && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |

**انتبه لـ`--include=dev`:** يضبط Render المتغيّر `NODE_ENV=production`، وعندها يتخطّى npm
حزم التطوير — ومنها TypeScript وVite — فيفشل البناء. هذه الراية تحلّ المشكلة.

متغيّرات البيئة المطلوبة على الخدمة: `TELEGRAM_BOT_TOKEN` و`SESSION_SECRET`.
لا تضبط `PORT` يدويًا (تضبطه المنصّة)، ولا تضبط `DEV_ALLOW_GUEST`.

على **Railway** نفس الأوامر تعمل، ويُقرأ الدومين العام تلقائيًا من `RAILWAY_PUBLIC_DOMAIN`.

### بوت تيليجرام (الرد على /start)

الخادم يستقبل تحديثات تيليجرام على `POST /api/telegram/webhook` عبر استدعاءات HTTP
مباشرة لـBot API — **بلا أي مكتبة بوت وبلا polling**.

- عند وصول `/start` يرد البوت برسالة ترحيب عربية وزر `web_app` يفتح اللعبة.
- في المجموعات يتحوّل الزر إلى رابط عادي، لأن أزرار Mini App مسموحة في المحادثات الخاصة فقط.
- يُسجَّل الـwebhook تلقائيًا عند الإقلاع **في الإنتاج فقط**، بعد بدء الاستماع،
  باستخدام `PUBLIC_URL` أو `RAILWAY_PUBLIC_DOMAIN` — بلا افتراض أي دومين ثابت.
- فشل التسجيل يُسجَّل في اللوق ولا يُسقط الخادم.
- كل تحديث يمرّ عبر `secret_token` بمقارنة ثابتة الزمن؛ غير المطابق يُرفض بـ401.
- الرد دائمًا 200 بعد قبول التحديث كي لا يعيد تيليجرام الإرسال بلا نهاية.

`GET /api/health` يعرض `bot: "enabled" | "disabled"` — البوت يُفعَّل فقط عند توفّر
`TELEGRAM_BOT_TOKEN` وعنوان عام معًا.

هذا المسار **لا يمس نظام التحقق من `initData`** إطلاقًا؛ الزر يفتح نفس الواجهة كما هي.

### حماية الإنتاج

عندما `NODE_ENV=production`:

- **دخول الضيف مغلق تلقائيًا** — تيليجرام هو السبيل الوحيد للدخول.
- **يرفض الخادم الإقلاع** إذا كان `SESSION_SECRET` ناقصًا أو ما زال قيمة التطوير،
  أو إذا كان `TELEGRAM_BOT_TOKEN` ناقصًا بلا بديل للدخول — مع رسالة تسمّي المتغيّر الناقص
  بدل تشغيل خادم مكشوف بصمت.

## بنية المشروع

```
packages/shared      عقود مشتركة بين الواجهة والخادم (أنواع، إعدادات، ألوان)
packages/game-core   محرك اللعبة: منطق خالص، بلا DOM وبلا شبكة
apps/server          Fastify + TypeScript + MongoDB (اختياري)
apps/miniapp         الواجهة: TypeScript + Canvas 2D + Vite (بلا إطار عمل)
```

### لماذا هذا التقسيم

`game-core` **محرك حتمي** بخطوة زمنية ثابتة: نفس البذرة + نفس الإدخالات ⇐ نفس النتيجة،
ولا يعتمد على المتصفح إطلاقًا. لذلك يمكن تشغيله لاحقًا على الخادم كمرجع موثوق
وإضافة WebSocket فوقه **دون إعادة كتابة اللعبة**.

- مصدر الإدخال مجرَّد خلف `ActorController`: اللاعب البشري، والبوت، ولاحقًا حزمة شبكة — كلها نفس الواجهة.
- الرسم منفصل تمامًا عن المنطق (`Renderer` يقرأ الحالة ولا يملكها).
- التخزين خلف `PlayerRepository`: مونغو أو ذاكرة، والتبديل لا يمس منطق اللعبة.
- عقد الطور الشبكي معرَّف في `apps/server/src/realtime/gateway.ts` وغير مُفعَّل بعد.

### قواعد اللعب المطبَّقة في المحرك

- داخل أرضك أنت آمن؛ خارجها يُرسم خلفك مسار.
- العودة إلى أرضك تُغلق المسار: المسار يصبح ملكًا لك، وكل فراغ محاصَر داخل أرضك يصبح لك.
- الارتطام بمسارك أنت ⇐ خروج من الجولة.
- قطع مسار خصم ⇐ إخراجه من الجولة (والبوتات تعود بعد مهلة).
- من يفقد كامل أرضه يخرج من الجولة.
- حدود الخريطة تمنع الحركة ولا تقتل.

### الأداء

- الشبكة مصفوفتان `Uint8Array` فقط — لا كائن لكل خلية.
- خوارزمية الاستحواذ تعمل داخل الصندوق المحيط بأرض اللاعب، لا على الخريطة كلها.
- الرسم يجمّع الخلايا المتجاورة بنفس المالك في مستطيل واحد، ولا يرسم شيئًا خارج الكاميرا.
- لا تخصيص كائنات داخل حلقة الإطار.
- القياس الفعلي: **60 إطارًا/ثانية** وذاكرة ثابتة عند ~10MB على شاشة 390×844 بكثافة 3×.

## داخل الجولة

- **الخريطة:** عالم أكبر من الشاشة بحدود واضحة، وكاميرا تلاحق اللاعب بنعومة (لحاق أسّي
  مستقل عن معدل الإطارات)، وخريطة مصغّرة في الزاوية السفلية تعرض حدود العالم وأراضي
  الجميع وإطار الكاميرا وموقع اللاعب. تُرسم على لوحة منفصلة وتُحدَّث على فترات، فلا
  تكلّف الإطار الواحد شيئًا.
- **لوحة الصدارة:** أعلى خمسة مشاركين بالمساحة، مع صف مستقل لمركز اللاعب إن كان خارجهم،
  وصورة تيليجرام لصفّه. صفوف ثابتة تُنشأ مرة واحدة ويُحدَّث نصها فقط.
- **وضع العرض:** عند بدء الجولة تُطلب `requestFullscreen()` و`lockOrientation('landscape')`
  من تيليجرام (Bot API 8.0)، وتُفكّان عند الخروج. العميل الذي لا يدعمهما يكمل اللعب بلا
  أي رسالة أو كسر. المساحات الآمنة تُقرأ من تيليجرام وإلا من `env()`.
- **مؤثر الإخراج:** ومضة قصيرة وشظايا وحلقة انفجار ولافتة `+10` عند نقطة القطع — كلها
  على الـCanvas بمجمّع ثابت الحجم، بلا عناصر DOM وبلا تخصيص أثناء اللعب.
- **العملات:** `KILL_REWARD_COINS` في `packages/shared` — موضع واحد للتعديل. العملات
  تُحتسب داخل الجولة وتظهر في الشريط العلوي وفي شاشة النتيجة. لا متجر ولا مشتريات ولا
  تخزين دائم بعد.

## الواجهة

- **الرئيسية:** بطاقة اللاعب (صورة تيليجرام، الاسم، اسم المستخدم، المستوى) وزر «العب الآن»
  مثبَّت فوق شريط التنقل كي يبقى ظاهرًا على أقصر الشاشات.
- **الملف الشخصي:** تبويب مستقل — يُفتح أيضًا بالضغط على بطاقة اللاعب — فيه الإحصاءات
  وبيانات الحساب، ومعرّف تيليجرام مخفي يظهر عند الطلب فقط.
- **تنقّل سفلي:** تبويبان فقط (الرئيسية / الملف الشخصي).
- **شاشة تجهيز الجولة** برسم يملأ رقعة خلية خلية، ثم شاشة اللعب، ثم شاشة النتيجة.
- **ثيم تيليجرام:** الواجهة تتبع الوضع الداكن والفاتح مع الحفاظ على هوية اللعبة،
  وتتكيّف مع ارتفاع WebView الفعلي بدل الاعتماد على `100dvh` وحده.
- كل النصوص عربية، والاتجاه RTL كامل.

## ما يعمل الآن

فتح Mini App ← قراءة مستخدم تيليجرام والتحقق منه في الخادم ← عرض الاسم والصورة ←
دخول الجولة ← حركة سلسة بعصا تحكم/لوحة مفاتيح ← مسار ← استحواذ على مساحة ←
بوتات بثلاثة مستويات تتحرك وتتوسّع وتهاجم ← نهاية الجولة ← شاشة النتيجة ← إعادة اللعب.

## ما لم يُبنَ بعد (المرحلة التالية)

Multiplayer حقيقي، WebSocket، Matchmaking، Leaderboard، تطوير أعمق لذكاء البوتات،
Skins، مهام، إنجازات، أصوات، لوحة إدارة، تحليلات، وأي نظام اقتصاد أو دفع.
كذلك لم يُبنَ بعد: نظام مستويات حقيقي، واحتساب مرات الفوز والمساحة الإجمالية
(تظهر بصفر في الملف الشخصي بدل أرقام مخترعة).
